# 大丑牌 Dachoupai

扑克构筑 Roguelike：通过出牌、弃牌、改造牌组与大丑牌连锁，完成一场荒诞巡演。品质目标对标 Balatro 的核心玩法和操作体验，视觉不照搬其素材与界面。

**当前候选是C00六角色/48牌的两章版本。** 已接入r2牌型/计分牌结算、成长、持牌、经济与风险效果，每场默认4次出牌/3次弃牌，以及商店和存档恢复。第二批新增重触发、四张普通顺子、手牌扩容、首购优惠、买卖成长、有限寿命与全局一次救场；原24张定义和六角色规则保留。阿默新局高牌Lv3，单张入口可用；其他角色/牌型默认Lv1，角色详情有构筑提示。两个章节目标为400/600/800与1000/1500/2000，压轴使用公开且固定的B01–B04之一，同局不重复。正式视觉、完整巡演和数值平衡仍有独立验收。

点选角色后，用固定的“确认角色”进入后台商店；详情和取消独立操作。商店点卡牌看大图、效果、余额与利息档，再确认购买；装备详情可左右调序，出售另有确认。手牌轻触选/取消，长按只查看；可按点数/花色排序或拖动，排序保留选择。Joker触摸长按后拖动调序。鼠标悬停抬牌/亮边，计分牌有描边和星标；出牌、弃牌是底部独立按钮。普通点分、角色、加倍率和乘倍率按真实事件逐个演出，来源高光/抖动、H/M滚数和声音同步，真实超额触发分级火焰/燃烧声。当前24张Joker都有独立东方插画和按需完整大图；牌组详情不公开抽牌顺序。窄/短屏采用紧凑布局，完整效果进入可滚动详情。

扩容后的手牌保留完整独立实例；放不下时可横滑或用左右导航，长按后拖动调序，排序和旋转不丢选牌。新24张使用标明“机制示意”的牌框图案，正式独立插画在A03小批验收。成长、寿命、救场和通关金币均沿真实来源演出并保存，刷新后回看不会再次加分、返钱或返还次数。

商店“本章节目”可提前看三个目标、压轴规则与应对方式，再确认是否跳场。暖场跳过得单次减2金券，正场得章开始已生成的公开物品，压轴不可跳；跳过没有过关奖金或利息。物品详情可升级已打出的牌型、给1～3张已知牌染色或恢复一次弃牌，不自动使用/销毁。满五槽买牌须先确认出售；成长属于原实例，出售后丢失。压轴失效牌有“失效”标记；低调点第4/5张普通点数为0，但成型及明确牌效果仍有效。

骰爷通常倍率 ×1.15，角色详情可选择本场押注一手，预览显示 50% 的两种可能结果。谢幕人详情显示最后一手状态。分数先计分牌、再角色、最后按装备顺序执行加乘；杂牌也会离手，但不给普通点数。旋转保留选择和确认内容，结算中旋转直接显示已保存的结果。

菜单可继续本局、导入/导出完整进度、调1×/2×/4×演出速度、背景音量/音效音量、减少动态、快进和回看上一手；版本信息显示实际构建SHA。两路音量默认22%/100%，0关闭并保存；背景为有来源记录的完整舒伯特钢琴《小夜曲》，首手势按需播放并跨场连续。出牌/购买先保存确定结果，再展示；未保存会暂停后续操作，可重试或导出内存结果。多标签默认只有一页可写，接管先读取最新进度。旧版或损坏数据保留可导出的备份。

当前六位东方巡演者在年龄、性别、职业、表情和角度上有区分。选角用256×320缩略，64CSS px HUD使用独立256×256头像，详情按需加载615×768完整立绘，母版不进public/首屏。用户已明确完成当前候选的真人核验并授权继续工程；尚未报告的具体设备场景、iPhone、多人专题和正式素材规格仍分别验收。

本次内容版本为 `quality-r2-content-v5`，内容hash包含48牌和实际能力。v4及更早存档原样保留并可导出，新版本需明确新开局，不静默续打或迁移旧局。完成两章显示“两章试玩完成”，不算八章巡演或无尽通关。

开发 AI 从 [AGENTS.md](AGENTS.md) 开始。人类阅读入口是 [审查与策划目录](docs/production/INDEX.md)。

后续玩法与M0–M9可测里程碑见[工作包](docs/production/WORK_PACKAGES.md)，缺项追踪见[内容合同第8节](docs/production/CONTENT.md)。C01按九个子步骤完成塔罗、12牌型星球、幻灵、7增强（含玻璃/幸运）、闪箔/全息/多彩3战力版次和12长期道具；随后C02补到72牌、C03完成八章/16Boss公开限制与无尽、C04补教学和模式。计划中的条目尚未启用，不代表现有画面已实现；多人专题、正式素材和最终签收仍分别验收。新会话读取AGENTS、handoff、plan.currentTask及其reads即可接续，不重启旧路线。

## 运行当前原型

```bash
npm ci
npm run dev
```

```bash
npm run verify
npx playwright install chromium firefox webkit
npm run verify:smoke
npm run test:e2e
npm run test:v00:sample
npm run test:v00:browser
npm run verify:ci
npm run test:rules
npm run test:run
npm run test:recovery
npm run test:recovery:browser
npm run test:layout
npm run test:layout:browser
npm run verify:content
npm run test:domain:browser
```

`verify:smoke` 检查构建产物上的选角确认、购买/取消、两种排序、弃牌、出牌与刷新续局；桌面鼠标和手机尺寸真实触摸。默认 Chromium，设置 `SMOKE_BROWSERS=chromium,firefox,webkit` 可在三个引擎运行同一短路径，CI使用此设置。仅测试构建开放只读几何/状态观察；操作始终通过实际输入。

按需设置`SMOKE_C00=1`补跑自然购买后的九张手牌、最后一手救场、刷新和只读回看；`SMOKE_C00=only`只跑这两条，`rescue`仅复核救场与最终失败转场。仅harness变动时可用`SMOKE_REUSE_BUILD=1`重用已记录指纹的`shots/smoke-build`，源码变动后须重新构建。

`verify:ci` 默认只执行单测、内容校验、构建、短用户路径、plan结构五项，拒绝期间的源码或 Git index/HEAD 改动。现有 `test:e2e`、恢复/布局长路径、120局诊断、V00代表种子、资产CLI与故障注入保留为按变更范围选择的诊断，不在每次提交重复执行。P00没有重跑的诊断不算新版本通过。

手机尺寸与浏览器模拟不能替代 Android 真机、视觉金样批准或真人体验验收。两章工程交付也不代表八章巡演或数值平衡通过。

`test:assets` / `verify:assets` 的A00只读校验已纳入main；按资产变更选择运行，不代表视觉、使用来源或预算获批。

`release:checked` 只执行只读检查，`--plan` 标 NOT_RUN；不会提交、推送或合并。

技术栈保留 Phaser 3、TypeScript、Vite、Vitest、Playwright；Blender 是离线素材工具，不是游戏运行时依赖。生产规范和阶段门禁见 [ROADMAP.md](ROADMAP.md)，当前任务见 [TODO.md](TODO.md)。
