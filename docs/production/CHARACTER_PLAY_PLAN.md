## 1. 最新目标与覆盖关系

玩家追逐的是组合与留弃牌决策：六人都可用两对、三条、顺子、同花、葫芦；对子过渡，高牌兜底；四条、同花顺难成但回报高，复制牌产生的五条/同花葫芦/同花五条仍由真实12型支持。角色区分成型手段、成长、经济、联动、风险与爆发时点，不是指定牌型职业。所有预选/指导仍无预计本手总分、累计H×M、预演来源或火档。

此方向覆盖“阿默靠单张×3/高牌成长加强”及“先做阿默采购优化”的后续推进；04d是已发布的阶段性数值补丁，旧局安全合同有效，不能称满足新玩法要求，也不擅自回滚。013264的18局小诊断仅说明当时策略/seed能过首章；原采购只识别T01、漏P01：seed B第二店买b04后仍4金且P01售价4，零升级有策略缺陷，不能归因货池不足。原报告/失败/来源身份按原commit保留。

D45历史不删，新规则只在新内容身份上线；v10/v11已保存局继续各自规则。C04图鉴/教程/历史/联网与正式B00/V01/L01专题保持暂停或原门槛，不由本原型自动重启。

## 3. 共用算法与资源底线

权威 `scoreR2.R2_BASE_SCORES`：Lv1高牌20/1、对子35/2、两对65/2、三条90/3、顺子125/4、同花140/4、葫芦210/5、四条320/7、同花顺450/9、五条700/10、同花葫芦850/12、同花五条1200/15。每级增量也只读同一表，缺失等级“未发现·Lv1基准”不写存档；升级不是发现。基础优先目录不是收益排名，等级/Joker会改变收益。

普通牌型唯一evaluate；四牌规则仍仅普通顺子/同花，同花顺5张，两规则同持4连续同花判普通同花。主手/有效核心由共享facts，B02仅第4/5主手普通点数0，B03/B04失效仍参与判型。公共候选不能看未来牌或RNG，不为角色偷偷生成理想卡。改牌仍走已有工具命令，硬手牌上限14及现有短屏容量窗口保持。

兼容危险点：当前v10/v11 hash从共享R2_JOKERS、资源/基础分/初始等级等常量计算；直接改全局A系定义或角色switch，不仅可能换掉旧hash，还会把新语义套旧run。P1先冻结旧定义/常量及两代身份，用新profile overlay/严格分派新角色、条件与初始等级；未证明旧实际score/journal/receipt保持前，不改公共定义。新状态是沿schema2按profile独立严格解析还是提升schema，须由保存验证决定，不能把新字段变成所有旧局都接受的optional。

AI与角色缓存须含本run profile、等级、完整库存静态规则、顺序/Boss公开快照、角色进度及revision；新全局角色公式不能倒灌旧v10/v11局。主facts首帧即时，成牌枚举不在每个toggle阻塞输入。B内部排序权限以父明确合同为准；本计划不授权新的ScorePreview流进选牌UI。

Q01关闭新角色全部能力；B08只按其公开合同停用计分/押注，整理/经济/成长部分须逐项声明，不能随意整体禁用或漏禁。B06/B15/B16只禁Joker计分/版次，静态/资源/经济仍有效。保存成功后才能切实际分数、触发高亮和响声。

## 4. 阿默首原型：领域、事实与UI合同

### 4.1 待复核的默认规格

- 主手1–5张正常判型；建议合格集合为两对/三条/顺子/同花/葫芦及更高型，**对子/高牌仍能正常出牌但不获助攻爆发**，最终资格需父复核。
- 从当前可见剩余手牌指定恰2张同点对子或恰3张同点三条；实例ID唯一，与主手完全不交。原型助攻×2/×4只是占位，落在整手Joker之后/final floor之前，不能继承新旧单张×3再叠乘。新原型起始高牌Lv3是否恢复正常基准也须决定。
- 默认不助攻。补牌增加2/3张能筛更多牌，单靠“副组真消耗”不证明代价足够。**建议第一原型每场至多一次助攻**，资格随正式提交消费、进场重置；是否采用由父复核。若改为不限次/另耗整理额度，须先证明不是每手必用，不能先默认无限免费循环。
- 主手无效核心与助攻遇B03/B04时要明确资格；建议助攻自身全部有效才能提供计分倍率，但失效牌仍可留给主手凑型。B08/Q01不得通过无倍率助攻白筛牌。这些是必须决策，不写成现行规则。

### 4.2 命令与保存候选（未实现）

保原 `PlayHand {selectedIds}` 与旧journal不变；建议新profile独有命令：

```json
{"runId":"本局ID","commandId":"唯一命令ID","expectedSeq":17,"action":{"type":"PlayAssistedHand","selectedIds":["主手实例…"],"assistIds":["副组实例…"]}}
```

新命令只在阿默、新profile、await-input且无pending保存时合法。领域从当前hand按座位排序两组，检查未知/重复/跨组相交、主手上限、真实判型、助攻组及可用资格；不信UI送来的type、×倍、资源或已用状态。取消只改UI草稿，不发命令。不助攻继续普通PlayHand；空助攻不能用特殊命令白领额外效果。旧profile拒绝新命令，不静默迁移。

保存候选为新profile的 `characterState`（角色tag、当场assistUsed等明确字段），以及trace的助攻身份/消耗集合快照。旧严格解析字段、receipt checksum、原trace都不能补写。`rawAction/rawState/score trace`、不变量、profile/hash与IndexedDB发现/备份需一起扩展，不能只给新TypeScript optional字段。

一次正式手只扣一次出牌、推进一次playIndex、成长/寿命/救场检查一次。助攻牌按原手序进入本场已用区；没有单独shuffle/回牌，按实际移走数量从既有drawPile补到原handLimit，缺牌按现有耗尽规则。补牌的额外可见量也是真实收益，必须纳决策验收。受候场席等影响的持牌减少必须可见。

### 4.3 四个集合必须分账

|集合|语义及现有hook边界|
|---|---|
|主手playedIds|仅这组判型、基础点数、打出张数、rank-groups、首末/原第3、a12/maxPlayedCount和章节牌型历史；其中附带牌照旧参与打出条件。|
|主手scoringIds / activeScoringIds|唯一evaluator及Boss筛选；只有有效核心跑普通点数、强化、版次、计分牌Joker与重触发。|
|assistConsumedIds|2/3张是实际消耗，非主手、非弃牌、非持牌；不产生牌点/强化/版次/重触发/幸运或玻璃随机/弃牌收益。用独立角色来源表示倍率与消耗，不伪装牌计分。|
|heldIds / validHeld|从起手去掉主手**与助攻**后才算；候场席/后台眼神/留声纸、d03成长、d12留手奖励不能继续吃已助攻的牌。|

不能把两组并入既有selectedIds（会突破5张并误触hooks），也不能只缩一个临时hand后丢失完整起手/失效快照。应先做共用纯facts及显式消耗集合，再让正式resolver/trace/检查点一致。`f09`助攻不等于成功弃牌；`d05/a07/c05/B14`不因助攻触发或计弃牌历史。关末、返次、救场/B15追加事件仍保留最终已提交完整trace。

### 4.4 UI职责边界（B发布后再交单一写窗口）

一条“主手牌型 / 助攻副组 / 本场资格”内联区域，复用手牌与详情，不开多层弹窗、不扩大巨大面板。主手仍≤5、原5:7角标与独立出牌区保持；副组用不盖角标的区分badge，显示“将一起用掉，不算主手/持牌”。不显示本手机器合计。

AI切仅选主手，不自动挑助攻、不自动出牌。主手改动使副组冲突/资格失效时清副组并明确提示；不得自动把另一牌移进副组。已有点数/花色收牌清两组及旧undo；手动编辑终止顾问旧undo；resize仅按ID保合法两组，不消费资格；新hand/离场取消草稿，菜单/详情返回保同revision草稿。撤销是同revision的整组快照；ghost和“换组”仍分明。

pointercancel/第二指保留已经明确选上的牌、终止手势，不偷偷提交；Escape取消当前草稿动作按现有用户合同。保存失败保同一pending候选、禁新命令/草稿重提交；retry不再消费牌或资格。回看读取原trace里的主/助两组，不从当前hand重建，不回填新选择。UI要求是后续实现合同，不修改B当前源码。

### 4.5 可玩与反刷退出条件

- `99 KK QQ 6 7`：主99KK+助QQ与保QQ继续追主葫芦有真实取舍；不是把三对误判成新牌型。
- `♥5678、♣9♦9、K2`：现在顺子会拆99，弃K2追保副组的主手有机会但无保证；不展示未来/成功概率。
- 同一可见起手分别不助/对子助/三条助，保留实际补牌量、余下可追组合、持牌收益损失、手数/资源；证明存在合理“不助攻/延后助攻”决策，不只证明×4大于×2。若任何副组都必用，先改额度/代价，不继续调大倍率。
- 高牌/对子不成爆发捷径；不共享实例、超过总可见牌数、无效/旧回调与失效助攻拒绝且run/RNG/资源不变。
- 正式提交、快进、回看、后台、重载、导出导入、重复命令、配额失败重试，只消费一次且按同profile复现；f06寿命/退款/安全网不形成连续助攻筛牌环。
- 390普通9牌、14牌、320容量窗口及844短横可内联选两组/取消/收牌，真44px操作；对OnePlus需真实设备确认，Canvas不能冒充。先少量同条件可玩候选与独立早评，不做大模拟或全图集。
