## 4. 阿默首原型：保留的领域、事实与UI合同来源

### 4.1 首原型历史提案（已决项以上方与阿默实际合同为准）

- 主手1–5张正常判型；建议合格集合为两对/三条/顺子/同花/葫芦及更高型，**对子/高牌仍能正常出牌但不获助攻爆发**，最终资格需父复核。
- 从当前可见剩余手牌指定恰2张同点对子或恰3张同点三条；实例ID唯一，与主手完全不交。原型助攻×2/×4只是占位，落在整手Joker之后/final floor之前，不能继承新旧单张×3再叠乘。新原型起始高牌Lv3是否恢复正常基准也须决定。
- 默认不助攻。补牌增加2/3张能筛更多牌，单靠“副组真消耗”不证明代价足够。**建议第一原型每场至多一次助攻**，资格随正式提交消费、进场重置；是否采用由父复核。若改为不限次/另耗整理额度，须先证明不是每手必用，不能先默认无限免费循环。
- 主手无效核心与助攻遇B03/B04时要明确资格；建议助攻自身全部有效才能提供计分倍率，但失效牌仍可留给主手凑型。B08/Q01不得通过无倍率助攻白筛牌。这些是必须决策，不写成现行规则。

### 4.2 首原型命令与保存候选（历史来源）

保原 `PlayHand {selectedIds}` 与旧journal不变；建议新profile独有命令：

```json
{"runId":"本局ID","commandId":"唯一命令ID","expectedSeq":17,"action":{"type":"PlayAssistedHand","selectedIds":["主手实例…"],"assistIds":["副组实例…"]}}
```

新命令只在阿默、新profile、await-input且无pending保存时合法。领域从当前hand按座位排序两组，检查未知/重复/跨组相交、主手上限、真实判型、助攻组及可用资格；不信UI送来的type、×倍、资源或已用状态。取消只改UI草稿，不发命令。不助攻继续普通PlayHand；空助攻不能用特殊命令白领额外效果。旧profile拒绝新命令，不静默迁移。

真人退出问题很具体：新手能用自己的话解释这一组为何触发、哪个是+倍率/×倍率/再算单牌；没有指定卡时能指出一种合法替代；知道何时留牌/留钱、何时弃牌/花钱；老手能说明从过渡到百万/亿的成长来源与断供代价。只会照配方、看不懂限制或升级后莫名断成长，均算未通过。真实提交后能看懂放大链，预测总分仍不开放。CI、数量或一次亿级分数不能替代这些问题的通过，也不替代OnePlus/GPU/听感与原发布门槛。
