# 大丑牌发动高光：W4体验补充
更新：2026-10-07。状态：高优先级待实现、待观感验收；不是已上线功能。

## 用户目标与排期
用户要求大丑牌发动有单独特写和类似格斗游戏“大招瞬间”的高光，并明确纳入整体体验计划，不强行插队。归属 DELIVERY_PLAN 的 W4（U07/U08/U10/U11、SG10），先修 PC 横屏回归并做双端验收；P1基础可理解反馈承接W3事实、必要W1状态验证、现有可读手绘素材与最小尺寸合同，不等待W2整批美术完成。P2关键特写/连锁/大分演出保留真实事件、稳定布局与必要组件依赖，再按首章受控样板接入；不挤掉 PC/手机共同验收。
只借鉴蓄势、短暂停顿、特写、爆发、收束的节奏，不复制第三方素材或整套演出。

本补充也约束大丑牌、工具、长期道具与商店优惠的全类效果反馈，不只修“换一身”或“采购证”两个案例。[W3交互与信息](DELIVERY_PLAN.md#w3-交互-信息与ai切)负责清晰事实、状态和可操作入口；[W4连锁与音频](DELIVERY_PLAN.md#w4-连锁与音频)消费同一真实事件并安排短反馈/重点特写。以下均为计划待实现，当前PC修复实机验收仍第一，不据此提前启动产品实现。本补充的基础/强化阶段仅用于W3/W4内部，不是完整项目总排序。原W0–W9主线保留：首章真实输入/布局、已有素材复用与必要共用组件、交互与共同构筑/经济自然证据先承接，再做受控关键演出。非阻断精修可局部后置，已准备素材的必要映射和复用不后置；总体美术质量仍待分项验收。

## 行为合同
1. 每次真实生效都有来源反馈：对应大丑牌亮起、轻抬或局部放大，显示名称、实际效果及必要触发原因。无真实事件不演出；封禁或未满足条件不能装作发动。
2. 每手关键发动可进入一次重点特写：使用已有清晰卡面、克制暗底或舞台外框、短停顿、强调音效，再回到牌桌结算。不得挡住必须阅读的数字或出现占位色块。
3. 连续触发保留事件顺序和来源身份，重复来源合并为短连锁反馈；不为每个重复事件播放完整停顿。用户要求的“每次能感知”不能变成只突出最终一张。
4. 成长类区分“本手读取已有成长”与“结算后新增、下手生效”；相乘类显示实际乘数；重触类标明再次计分的对象。总分来自现有真实结算，不恢复出牌前预计总分。
5. 无评分收益的资源/成长触发也有简洁对应反馈，不用大分强度误导玩家。

## 统一效果反馈合同：来源 → 条件 → 真实收益 → 去向 → 下一步

每个真实生效事件都采用同一条可读链路；允许先用短句呈现核心变化，再查看详情，不把关键事实藏到必须长按或读完整动画才能知道的位置。

1. **来源：** 说明实际大丑牌、工具、长期道具或优惠来源的名称与身份；多来源按真实事件顺序保留，不能只留下最终一张。未触发、被封禁或实际增量为零时，不亮起成“已获益”；其条件状态可在静态详情解释。
2. **条件：** 说明本次真实满足的条件、对象、时点及次数限制，区分本手、本场、每店和下次生效。只读当前局profile、已保存事件与可靠状态，不拿全局候选文案覆盖旧局规则。
3. **真实收益：** 显示实际工具名称及数量、金币增减、原价→实付→实际省额、成长读取/新增、乘数、重触对象或代价减免。名义额度与实际到账分开；没有新增收益不能用领取/成长高光暗示已经新增。真实计分读取既有成长可以反馈其本手贡献，但必须标明“读取已有”，不能冒称新增成长。
4. **去向：** 明确进入工具包、金币余额、成长记录或本次计分/支付；满槽替代奖励、上限截断与下手生效另行说明。当前状态与事件已知时准确展示名称、数量、余额或进度，配对应查看入口；未知内容不得猜测或编造。
5. **下一步：** 给出玩家当前能做的动作，例如查看工具包、选工具→选目标牌→确认使用、查看本次计分来源、查看成长记录或继续购物；同时说明“优惠已用”“下店恢复”等当前限制。PC鼠标和手机触控都能读清并操作，不自动替玩家使用物品、提交牌或再次领奖。

| 效果类别 | 核心反馈与边界 |
| --- | --- |
| 赠送 | 谁因何赠送、实际物品名/数量、到账位置、查看/使用入口；满槽时显示实际替代收益，不展示虚假已入包物品。 |
| 返利 | 来源、触发交易/结算、真实返还额与入账余额；零返还或上限截断不能亮成完整名义返利。 |
| 折扣 | 原价→实付→实际省额，逐来源的真实读取/贡献与最低价截断；本店使用状态和恢复时点清楚。 |
| 成长读取 | 本手读取的已有值、实际影响与来源；不新增成长，不显示再次领取。 |
| 成长新增 | 本次实际增量、保存后累计值、何时开始生效；明确结算后新增不倒灌到本手。 |
| 重触 | 哪个来源令哪张牌/哪个对象再次计分、实际次数与本次结果；重复来源合并短连锁，保留真实顺序与对象。 |
| 代价减免 | 原代价、实付代价与实际少付，涉及金币/弃牌次数等资源时分别注明；不把“少付”误写成额外赠送。 |

### 已核规则样板：换一身与采购证

以下是基线规则与待实现展示合同，不是用户当前局奖励记录；尚未读取用户当局奖励，不填写某件工具已到账或某笔购买已省钱的虚假实例。基线定义见[r2-jokers.json](../../src/content/r2-jokers.json)、[r2-tools.json](../../src/content/r2-tools.json)与[r2Shop.ts](../../src/domain/r2Shop.ts)。

- **c12“换一身”：** 同一场实际打过普通straight和普通flush并成功过关，从T03–T06随机获得一件；不是打出任一牌型就赠送，也不以特殊/升级牌型冒充普通条件。事件已知时显示真实工具名称、数量1与“已放入工具包”，提供工具包查看入口。玩家在工具包选工具、选适用目标牌并确认使用，不自动染色。满consumables槽时明确“工具包已满，转为2金币”及实际入账去向，不能同时展示已获工具和2金币。
- **U10“采购证”：** 长期道具，每店第一笔购买减1，最低付1；买采购证自身不享受，不是每笔减1。显示本次原价、实付与实际省额；优惠是否已用及下店恢复由当前店购买状态决定，不能承诺本店第二笔仍可用，也不能把购买采购证自身演成获得首购减免。
- **多来源优惠与最低价：** 名义可用额度不等于实际省额。各来源只声明真实事件记录的贡献；最低价截断后的总省额不能被每个来源重复认领。事件若仅提供合计及已读取来源，先如实显示合计与来源列表，不猜拆分额；需要新增归因事实时先在W3明确事件合同及领域边界，不能在表现层自行倒推、改价或创造收益。实际省额为零的来源不亮成已省钱。

### 统一反馈与中断验收

赠送、返利、折扣、成长读取/新增、重触、代价减免都进入同一真实来源合同：P1先以清晰文字、实际数值和普通短反馈闭环；P2关键发动才用重点特写；资源/经营收益不套用胜利大分的强度。短反馈结束后仍能查看已保存事实和下一步入口，PC与手机均不得遮住关键数值或挡住可用操作。

跳过、刷新、切后台与恢复只改变展示进度，不重复发奖、返利、减价、成长或重触计分；恢复展示已保存结果，不重新执行获益命令。对同一已保存事件，正常、快速、跳过及恢复后的最终工具包、金币、成长、购买状态和计分必须完全一致。验收应加入槽满转2金、优惠已用、买采购证自身、多来源折扣受最低价截断、零实际收益及旧局profile对照，记录玩家能否复述来源、条件、真实收益、去向与下一步。上述仍待实现、待真实trace及PC/手机观感验收，不以这笔文档提交宣称完成。

## 强化演出的首个受控样板（P2建议值，待实际观感校准）
- 普通来源反馈约120–180ms，可与计分同步。
- 重点特写总长约450–700ms，关键停顿约80–120ms；每手默认至多一次完整特写，其余缩短衔接。
- 连锁演出新增阻塞时间暂以每手不超过1.5秒为样板预算；原结算节奏单独测量，避免把预算误当整个结算时长。
- 默认/快速/低动态三种表现：快速压缩特写与停顿；低动态取消震动和大幅缩放，仍保留来源与数值反馈。提供明显的跳过/加速入口，鼠标与触控都能用。
- 不新增专用CG或整套人物动画；先用已有卡面、共用UI及现有音效做一个代表样板。两次同方法改动仍不能改善则重审节奏，不批量重画。

## 技术与中断边界
表现只消费已成功保存的结算事件，不改领域计分、随机、牌型、奖励、存档身份。跳过、切后台、恢复、重复点击、窗口缩放或横竖屏切换，不得重放奖励、重复增长、卡住输入或把旧动画回调作用到新局。动画资源缺失时退化成可读的静态来源反馈。
现有背景音30%、音效80%默认合同保留；短强调音效不得因重触叠成过响爆音。不要高频全屏闪烁。

## 验收与证据
- 同一批固定真实trace覆盖：普通加成、倍率相乘、重复触发、跨多个来源连锁、成长读取/新增、封禁未触发、胜利大分、跳过与后台恢复。
- PC至少1280×720、1366×768、1920×1080；手机390×740、320窄屏与短横屏，并测窗口动态变化。不可仅用竖屏样稿签收PC。
- 玩家在演出后能指出哪张大丑牌发动、为何生效、改变了什么；原牌桌关键数值可读，操作恢复明确。
- 比较正常播放、快速、跳过、后台恢复的最终状态完全一致；无一帧异常色块、遮字或重复奖励。
- 观感、实机流畅度、音频听感分别留证；软件截图、测试数量和文档不得代替真机/用户满意。首轮只需有限关键短片与截图，不反复长录屏。
- 拒收：必须关特效才能看清、普通每次都长停顿、关键来源看不懂、PC和手机只过一端。
