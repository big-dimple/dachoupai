# 操作、信息与音画反馈合同

所有尺寸/延迟是本项目目标，尚无目标设备实测结论。最终记录必须同时注明 CSS 像素、设备 DPR、浏览器版本、构建与输入方式。

## 1. 不把桌面缩小当手机适配

竖屏以可用宽度 360–430 CSS px 为首要布局；桌面以 1280×720 以上为目标，同时测试 1024×768；横屏手机至少测 844×390，平板测 768×1024。320px 窄屏提供同一套可滚动详情/紧凑布局或明确支持提示，不偷偷把正文缩成几像素。

竖屏分区：顶部局/目标/资源（约 12% 高）→Joker 槽与展开入口（约 16%）→中央计分与选牌预览（约 25%）→可操作手牌（约 30%）→固定操作栏（余下，含安全区）。百分比只是排布起点，最小点击与文字尺寸优先，空间不足折叠低频信息，不缩小出牌按钮。

桌面采用侧边局信息、上方构筑区、中央得分、下方手牌与操作；不要把标题、SEED 和全角色台词占据关键空间。SEED/版本放设置或局详情，开发调试信息不成为正式 HUD。

主操作命中区至少 48×48 CSS px，次操作至少 44×44；高频正文至少 14px，主要数值 22px 以上。手牌允许重叠，但每张至少有 36px 宽独立可点击露出区域，并提供抬起/放大状态；窄屏允许水平卡带和稳定聚焦，不做两行随机换位。

使用纯函数 layout(viewport,safeInsets,mode) 返回各区域和命中框，再由 Phaser 渲染。resize 改视图，不重建本局；DPR 只改变清晰度预算，不改变 CSS 点击面积。方向切换、浏览器地址栏伸缩后选择与确认状态保留。

D16增加真实浏览器栏占高的390×740、360×640与844×300检查，高DPR触摸不能用一倍像素画布放大代替。菜单开关使用同一固定触发按钮，保留未提交选牌；旁边提供真实全屏/退出入口。自动横屏与隐藏浏览器栏仅是浏览器请求，未获允许必须如实提示并保留操作，尺寸仿真通过不算Android实机通过。

## 2. 输入语义

| 行动 | 鼠标/键盘 | 触摸 | 防误操作 |
| --- | --- | --- | --- |
| 选/取消手牌 | 单击；方向键聚焦+空格 | 轻触 | 抬起与描边双反馈；第六张给明确上限提示 |
| 查看详情 | 悬浮/右键；Enter 详情 | 长按约 350ms 或详情按钮 | 详情不会顺带选牌/购买；拖动后不误认点击 |
| 出牌 | 独立按钮；快捷键可设置 | 底部明确出牌按钮 | 0 张/结算中禁用且说明原因；短按卡牌绝不直接出牌 |
| 弃牌 | 独立按钮 | 与出牌分开、样式不同 | 显示剩余次数，默认无需二次弹窗；最后一次可选确认设置 |
| 排序 | 点数/花色切换 | 两个大触点或分段控制 | 不消费 RNG；保留选择，拖动排序与横向浏览有阈值 |
| Joker 调序 | 拖动，键盘移动 | 长按后拖到槽；亦可详情内左移/右移 | 插入预览和落点；不能与卖出共用手势 |
| 购买 | 选中货品→购买按钮 | 同桌面 | 只点卡面打开详情，不即时扣款；成功反馈价格/金币变化 |
| 出售 | 详情内出售→确认 | 同桌面 | 明确实例/售价/成长将丢失；确认可取消 |
| 退出/重开 | 菜单 | 菜单 | 有进行中的局先提示，保存成功才离开 |

快捷键不能在文本框输入 seed 时触发游戏操作。焦点有可见轮廓，颜色不是唯一信息载体。取消手势、触点移出、系统触控打断要产生 pointercancel 清理，不遗留拖拽锁。

## 3. 决策前的信息

常驻：当前分/目标、剩余出牌与弃牌、金币、计分预览、选中数量。Joker 上只放可读名称和关键当前值，完整效果进入详情；别在小卡上塞 10px 多行说明。

手机首屏以目标、当前手牌和出/弃牌为主焦点。排序、牌组、规则用短标题的44px工具入口；牌堆统计、上一手日志与完整能力进入对应详情。商店卡面展示名称、简短用途和价格，点选后查看完整条件与明确购买确认；空槽使用低对比牌背，进入牌桌占独立主按钮行。短屏空间不足时，计分牌用可读点数/花色列示并保留手牌高亮，不塞微缩说明或被截断的人头画。

预览显示识别牌型、等级、计分牌高亮、确定基础热度/倍率。随机部分标明概率和范围/两种结果，不能将平均值画成保证分数，也不能偷读下一次 RNG。显示“需至少再获得 X 分”比一句泛泛鼓励更有帮助。

牌组查看支持剩余/全部切换、花色/点数计数、增强筛选与已用标识；不得展示未抽牌的具体排序。商店详情能比较当前构筑、当前成长、售价、购买后余额与利息档，不替玩家自动决定。

Boss 规则在本章开始、选场和场内都可查，受影响牌有符号提示；封禁不是只改成难以辨认的灰色。非法行动拒绝必须解释具体原因，并保持原选择不消耗资源。

C03的完整盲注提示沿现有暖场/正场/压轴扩展：确认进入前显示本场目标、限制及一句应对，牌桌保留简短规则入口。人头/花色受限的牌要说明仍成型但何种收益停用；第4/5张点数抑制不能标成整牌失效，Joker封禁不能抹掉仍有效的静态/经济能力。开场不强制读长文，详情可随时回看，恢复/旋转不重新抽规则。

C01新增功能沿同一精致详情和目标确认，不给塔罗/星球/幻灵各造一套菜单。星球显示目标牌型等级及前后H/M；改组显示所选实例和替换损失；幻灵先显示代价、合法目标和公开概率。扑克/Joker分别显示增强、版次、稀有度、失效原因，不能靠小图彩光暗示规则。实际新增收益必须逐来源高光/抖动、滚数和独立音效，物品使用后计分区/库存/牌组同步；未触发或被封禁的加成不演成功，快进与减少动态仍读得懂。

## 4. 结算节奏

一次手牌只允许一个主焦点：出牌落位→牌型与点数→计分牌逐张→角色→Joker 链→总分入账。H、M、最终分三处数字对应 trace 的真实变化。+倍率与×倍率有不同符号与声音，不在没有触发时让整排牌一起亮。

按D22调整D18过慢的节拍：选择反馈首帧仍以80ms为目标；默认1×逐事件演出，不按整手长度压缩、不折叠计分重触发。每条计算仍经过来源预备、飞入、数字命中、余韵；普通扑克从约0.5秒逐步加速至约0.3秒，角色约0.6–0.8秒，加倍率约0.4–0.6秒，乘倍率保留约0.9–1.1秒蓄力/命中停顿。事件越多节奏渐进，但每个来源保持可辨识的下限；重触发仍逐次高光，不合并数字。来源越多整手自然更长，2×/4×和快进由玩家选择。以上是设计目标，实际时长与目标设备实测单列。

速度 1×/2×/4× 可切换且持久化；加速只改变播放映射。支持按住/按钮快进当前手，结算日志仍完整。结算中误点出牌不能排队自动打下一手。按退出先确认，再以已确定结果保存并结束动画。

大爆分的震动/闪光按“相对目标和本局历史”的层级决定，不是每次过关都全屏闪白。默认轻震、减少动态选项完全关闭相机震动和强闪；无额外分数时不演大爆炸。前景粒子不遮挡卡牌点数、按钮或 Boss 规则。

P04按D17补齐失败资源反馈：出牌/弃牌余额独立大数字；命令成功提交后立即更新，实际净扣除与数字弹跳、短音同步；最后可用机会变色，零机会明确禁用。双弃成本按剩余可操作次数判断，首弃返还不虚报扣除。回看、保存失败和重复命令不重播资源扣除。普通达标、累计2/3/5倍目标的印章与终结音逐级加强，标明本场倍率；不虚造存档成就或奖励。减少动态保留静态扣除/达标提示。

动作按钮没有“长按看详情”时，在原触点按住再松开仍只触发一次；不能套用卡牌350ms长按门槛而吞掉出/弃牌。移动拖离和pointercancel依然取消；卡牌长按仍只打开详情。

## 5. 音频

应用内部保留Master/Music/SFX/UI总线；P06按D19只向玩家提供“背景音量”“音效音量”两条0–100%滑杆，0即关闭。默认背景22%、音效100%，UI跟随音效；不再显示静音、关闭背景音乐或总音量控件。独立持久化两路数值，旧静音迁移为可见0%、旧总量折入两路，避免隐藏开关让滑杆失效。首次用户手势解锁，播放失败不阻断命令；后台暂停，回来恢复同一音乐实例。

最低声集：选择/取消、无效操作、出牌、弃牌、点数累加、+倍率、×倍率、重触发、购买/出售、刷新、成功、失败、稀有揭示。连锁音高按事件层级有限上升，设上限与动态范围，不能 20 次触发后刺耳爆音。低音量下仍能区分阶段，静音时靠视觉完全可理解。

P06依用户最新要求替换P05肖邦自制改编为有可核对来源的舒伯特小夜曲D957/4钢琴音轨。保留完整主旋律、原调和录音节奏，跨场连续，首手势按需加载；不叠加自制鼓点/旋律或变速变调，不用竞品音轨。Stem Music不在当前范围。

逐来源数字滚动对应有界颗粒/咕噜声；热度、倍率、总分不同音色，加乘力度不同。弃牌为降落滑声、出牌为上扬滑声、购买为金币与纸牌，稀有揭示多一层短泛音；只有实际事件触发。滚声不逐帧创建音源，与1×/2×/4×演出真实持续时间对应；取消、快进、后台及音效0及时清理，音乐音量不改变SFX力度。

P05当前显示的本手H×M加此前累计超过目标时，数字周围燃烧，火声随超额级别增加；火焰不遮文字/手牌/按钮。加热度、加倍率、乘倍率、重触发、失效提示音色不同，只有真实来源参与。减少动态保留静态超目标标记，取消/后台/静音停火声；火焰不代表提前入账或未来押注成功。

D22将初版细条火舌升级为有层次的热浪、暖光底焰、卷动火舌与余烬；跨过目标/2倍/3倍时短暂升温，保持中间数字清楚。强度仍取当前实际显示值，押注扣分后能熄灭，重播不重复入账；使用有界2D绘制/资源池，减少动态只留静态暖边，退出和重建清理。

P04先修正过低的源电平，再调整总线与压缩；最大音量有可用响度，零音量/静音严格无声。原创主题使用重复动机、回答乐句和留白；计分命中时音乐短暂让位，累计超额时终结音只播一组。离线波形峰值/RMS与真实音源排程只能证明工程混音，Android实际外放/耳机试听仍必须单列NOT_RUN。

## 6. 教程与复盘

教学给固定可复现的局部手牌，步骤只指向当前必要动作；用户实际完成才消失，不用时间延迟假装学会。读过扑克牌的人可直接跳过；没读过的人能在详情看例子。完整图鉴可查牌型计分集合，不只列扑克大小。

失败页给：差额、最后几手得分、主要来源、资源余量、当前构筑；提供回看最后一手、同 seed 重试、新 seed 新局。提示来自可解释的实际数据，例如“还有 2 次弃牌未使用”，不编造“只差运气”。胜利页给有效成长/流派摘要与继续无尽，不把所有统计密密麻麻堆首屏。

## 7. 必须覆盖的 UI 状态

启动加载/超时/单资源失败、无存档/可继续/坏存档、选角确认、首店/空店/钱不足/满槽、零选择/超选/无弃牌/空牌堆、押注未选/已选、Boss 拒绝、计分各阶段/快进/取消、商店恢复、方向切换、后台恢复、胜败、导入失败、版本不兼容、多标签只读。

每个状态必须有文案、可恢复行动和明确禁用行为；占位只允许在灰盒阶段，正式版本不能露出“TODO/功能开发中”的死按钮。读屏与完整无障碍范围若尚未完成须明确记录，不能仅凭 Canvas 有文字就宣称可访问性合格。

## 8. 对标任务

用同类操作任务比较：选择并取消五张牌、弃牌凑同花、查某张 Joker 当前值、买替换牌、调顺序预测效果、理解一次连锁、解释一局失败、恢复中断的一局。记录误触、找不到功能、任务用时、理解错误和主观控制感。对标不是比较首页截图豪华程度；具体样本和判定见 QUALITY。
