日期：2026-10-13 UTC。用户要求重新评审当前 GitHub 与开发计划，并将结论交给执行助手。本轮只写审查文档，不改产品、不合并其他 PR、不部署。本文是现有 [DELIVERY_PLAN](../../DELIVERY_PLAN.md#当前统一执行计划) 的审查输入，不新建另一条实施队列。

## 给统筹与执行者的结论

**有真实进展，但当前还不能签“整局品质已经收敛”。最危险的已不是上轮单纯成长不足，而是自动过关倍率遮住了做牌、采购和英雄的价值；同时，新数值方案、旧排程和角色入口的状态不一致，继续各自扩写很容易返工。**

建议立即这样接续，而不是全面停工：

1. 接续 PR154“削减自动指数、同步公开目标”的方向，进入一个有界实现候选；不再增加同目的的新分析支线，也不要求先重跑十八局。cap-max ×4 和新目标表仍是试验参数，不是已经平衡。
2. 规则身份、目标入口、计分时点、来源事件由一个集成者先定接口；其他人可以并行做独立呈现、针对性反例和证据，不能同时改这几个共享规则文件。
3. 推荐只先补真实条件、指定替换成本和下面的 c07 可用性反例，不在这个窗口重新设计全局五星、价格或存钱连乘。
4. 已有结算/失败候选允许独立收尾，但只消费实际已保存事件；新的英雄首屏、拖拽扩展和美术原型不夹带规则改变。复用现有手绘，不推倒重写。
5. 把原计划的下一验收点改为“同一新规则下，买/不买、做牌/不做、发动/保留真的改变后续选择”，而不是继续累计局部截图、提交或检查数量。

这不是发现了主线已经发生文件覆盖的证据。现有仓库确有失败留证、原子交易和独立候选边界；问题是这些局部约束尚未自动组成同版的完整体验。

## 3. 六个优先问题与复现/验收要求

### F01 — 自动过关乘区挤占构筑价值（P1，源码确认；体验比例来自仓库报告）

**证据与根因。** [r2RouteGrowth][S1] 把成长归本局，不占 Joker 槽、不要求新采购。前三次对应合格清场后，G/S/F每次分别乘1.35/1.4/1.3；各族上限10^12，复合牌型逐族相乘，没有整手统一上限。[scoreR2][S2] 在整手Joker后逐族读取；成功清场才累计，新增不回灌本手。这里没有据源码发现重复读取或回灌，不能把大数一概报算术Bug。

假设每章三场都真正过关且该族都合格、尚未触顶，自动因子每章增长如下。当前无尽目标每章×2.4，见 [r2Chapter][S6]：

| 路线/复合型 | 每章自动倍率增长 | 与目标增长的关系 |
|---|---:|---|
| G，包括对子 | 2.460375 | 稍快于2.4 |
| S | 2.744 | 快于2.4 |
| 普通F | 2.197 | 慢于2.4，不能说所有单路线都自动跑赢目标 |
| GF | 5.405443875 | 显著快于2.4 |
| SF | 6.028568 | 显著快于2.4 |

这些是条件增长率，不保证抽牌、过关或自然胜率。它们解释为什么“低投入对子长期续推”和“复合型异常拉开差距”可以同时发生。

仓库 [18局复盘][S10] 记载C2五局第5–8章60场全部首手过、多人后期少采购/少用主动。但这是跨版本试玩报告，本轮未拿到其原逐场账和全部图片，不能将60/60外推为总体比例。

**处理。** 支持PR154有限加成且复合型不重复领自动乘区。高分尽量由牌型等级、增强/版次、重触、Joker成长与英雄实际动作产生。不能只按当前巨分抬目标，也不能靠额外存钱自动连乘替代旧自动指数。

**验收。** 固定公开状态分别列无过关加成/实际过关加成、改牌前后、英雄用/不用和真买/不买的结果；再以正常操作核实际选择。允许成熟好构筑一击过关，不设强制多手或免死盾。降低自动因子不能以“旧绝对峰值无损保留”宣传。

### F02 — cap-max4方向合理，但目标表与中期获得性没有闭环（P1，候选设计风险，不是当前产品Bug）

[PR154固定文档][S11] 已诚实写明：六个Lv5配方、已成熟实例、预先给定的互不重用 ready-hand 供给，主要用于结构和资源边界；没有证明早中期真实商店能形成这些状态。972切片和162区间不能变成自然通过率。

**两个特别需要防返工的点：**

- 沿用当前速率但封×4，G/S在第8次对应合格清关后、F在第9次后即达到上限，下一手读取。连续同路线约第三章末/第四章起就停止这条成长，后面必须由实际经营接上。不能只检查第13章。
- 旧G14所列完整末手公式独立复算为310,793,589；仅把其S自动因子换成×4为2,912,241。候选第8章压轴基础目标40,950；若有一次B14弃牌增目标，则42,998。这个投影依然有大幅超额，证明“封4”本身不等于Boss压力已恢复。它不是新规则自然到达证明，也不是要求这类成熟手不能秒杀。

**处理。** 不再无限扩影子扫描或另开全局调价。将一个明确候选接到真实新局，沿现有计划进行小规模同版早中后期验证；精确cap/目标允许据结果调整。低难主线与自选挑战是不同验收目标，q=3样例不能代签D0。预选q与现行D1–D3的映射本包没做，就保持未做，不暗中新增第二套菜单。

**最小验收。** 三条正常路线各预登记一局，固定规则，正常随机，不因失败重开筛选；失败、未出现的工具都保留。至少能从记录读出第二、第四、第六章遇到的目标、预算和采购/成长；自然早败也作为结果，不要求为了凑齐后段伪造成功。未出现的关键边界只补定向夹具，不重跑十八局作前置。新规则下没有自然千万/上亿路线，就如实留待验证；不能用旧G14盖章。

### F03 — 新目标不能直接改全局常量再删校验让测试过（P1，已确认的集成风险；当前未发生启动故障）

[r2Run.ts][S12] 在模块加载时，将 `R2_TARGETS`、`R2_ENDLESS_CONTRACT` 等算入 `sharedRuntimeHash`，与 `R2_LEGACY_CONTENT_HASH` 比较，不同即抛 `published-r2-contract-drift`。因此，**只改r2Chapter的共享目标而未处理规则边界，会连新局启动都一起破坏**。这不是当前main已崩溃，而是PR154落地必须显式处理的调用链。

身份还通过 [r2GroupUpgrade][S4] 的继承hash、[r2ContentProfiles][S9] 的精确选择进入工具/英雄/推荐。只让孤立scorer例成功，不证明普通菜单真正进入了新合同。

**建议最小实现。** 新规则有明确身份和目标配置，统一的目标读取入口被新局、入场、预告和保存使用；先锁入场目标，所有因子最后一次ceil。旧全局冻结定义不要被无意改成新规则。若按最新需求不再支持旧局继续，可保留导出/历史、清楚提示重开，不做旧档迁移大矩阵；仍不得静默读成新规则、删档或通过移除完整性校验掩盖混用。

**共同事件合同。** 实际选择的“本手相关族最大因子”只入账一次；不是跨所有历史族随便取最大，也不是UI写×4而scorer仍乘两次。未选中族可以作为详情，但不能演成它们都贡献了分数。保留已合的新补牌核心、主动后置、真实燃金及购后余额。B14基于锁定初始目标计增量，刷新/重试不重新抬价。

**验收。** 从正常选角进入新局；目标预告=入场锁值=刷新恢复值；GF/SF非对称族积累验证max而非product；手后新增下一手生效；反复确认/保存失败重试不重复结算；实际结果来源与最终一次floor相符。先锁这些接口，再让数值、结算和说明线程并行接入。

### F04 — c07推荐算出了“不可触发”，却没用这个结果拦住高推荐（P1，源码条件不一致确认；完整运行夹具待执行）

**实际规则。** c07“拖个尾音”只接受普通flush/straight-flush，见 [原始定义第36行附近][S8]。它不在当前六牌覆盖中；继承层 [Assist][S14]、[Combo][S15]、[Group][S16] 也不改c07。不能把已修的c06家族兼容算到c07头上。

**实际推荐。** [ShopRecommendation][S7] 前段已经计算 `ordinaryFlushPossible` 和 `flushRetriggerPossible`，并注释c07范围比F家族窄；但 `case 'flush-retrigger'` 只按 `largestSuit/flushReady/boosted` 等给星，没有使用这个可触发见证。

**静态构造反例。** 当前规则、同花focus、无Boss封禁/现金降星：公开活牌组为52张同点同色牌（例如6♥，实例ID不同），其中至少一张有有效计分增强。任取1–5张，只会得到高牌/对子/三条/四条/同花五条，绝无普通同花或同花顺，见 [evaluateR2Hand][S13]。于是c07触发条件无见证，但 `flushReady && cards.some(boosted)` 走四星分支。是否自然获得这种牌组本轮未测；本轮也未调用完整shopRecommendation，这里是明确构造条件下的源码推演和独立分类核对。

**玩家影响。** 推荐的“条件就绪”与当前实际可用性脱节，容易诱导为一张当前牌组根本无法发动的卡腾位。它不是“星数不保证下手抽到”的正常不确定性，而是所有合法主手均不满足。若设计想推荐未来转型，必须明确还缺什么，不能当已有配合。

**处理与验收。** 先在当前主线加合法领域夹具确认；以真实可达牌型条件作为推荐前置，普通同花/SF保正例，纯同花五条保负例，补四张同花规则边界和Boss封禁。若保持c07普通型专精，清楚呈现高级型失去它的取舍；本包不要顺便扩成全家族、给全库重打星。保留PR148/149/153，不回滚它们来修这个反例。

### F05 — “当前执行入口”仍发出已过期的任务状态（P1，文档矛盾确认；并非已证明代理照此误执行）

[AGENTS顶部][S17] 仍写2026-10-11只整理文档、产品暂停、额度恢复后串行；[CHARACTER_PLAY_PLAN顶部][S18] 仍写main=57b63dd、骰爷弃前未成、新核心和主动后置尚未实施。与此同时 [当前DELIVERY_PLAN][S19] 已记录PR130/134等已合。

**处理。** 统筹只更新三处的短当前入口：实际规则身份、已完成项、当前活动包、文件所有权、验收出口；旧正文改为明确历史引用而不删证据。角色页只维护角色事实，排程仍指唯一DELIVERY_PLAN。PR135等旧整文件候选逐段提取仍有效内容，不整份覆盖当前计划。

**验收。** 新执行者只看当前入口与本次任务，就能答出：正在用哪套规则；哪些已合不必重做；自己能改哪些文件；最后由谁集成。不存在同一项在当前段同时“已合”和“未实现”。不增加第四份长期总计划，也不恢复大段历史审查复述。

### F06 — 整条体验的同版证据仍弱于局部工程证据（P1，证据范围确认；美学本轮不判通过/失败）

**验收。** 当前规则的正常新局初值、关键交易前后、终态/失败及对应来源至少可回查；结果、预览和实际扣费不矛盾。PC1366、手机390/320、短横屏和安全区定向覆盖；真机触感/音频与软件浏览器分签。新的头像首屏应人物为主、例牌主动展开，但先复用现有资产做一屏有限对照，不把整套重画插入数值集成。

from fractions import Fraction as F
floor = lambda x: x.numerator // x.denominator
ceil = lambda x: -(-x.numerator // x.denominator)

assert floor(59 * 30 * G**32) == 26_221_278

warm13 = F(20_475) * F(11,10)**5
assert [ceil(warm13*x) for x in (F(1), F(3,2), F(2))] == [32976,49463,65951]
assert [ceil(warm13*x*3) for x in (F(1), F(3,2), F(2))] == [98926,148389,197852]
