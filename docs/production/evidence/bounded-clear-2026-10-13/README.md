## 实际实现

所选路线的新局统一使用 `quality-r2-bounded-clear-v1` / `json-fnv-v1:594ea97e197917ba`。新规则必须新开局，原同输入绝对分数会下降，需要重新建立构筑。旧历史不删除，现有旧身份实现没有额外扩建；当前新规则的保存、刷新、重复命令与真实结算闭合保持。

- 合格主手按原G/S/F资格和各自真实清关历史读取；前三次宽限，之后原1.35/1.4/1.3增长，只增到4。
- 一手只取符合主手的最高族因子，平手G/S/F固定顺序。GF/SF不再叠乘；高牌无族，因子1且无额外乘法事件。
- 清关资格仍按实际出过的主手，成功清关一次，各族累计；本手只读手前值，新增不倒灌，不由初选路线/持有牌/最高分决定。
- 做牌、等级、增强/版次、重触发、Joker经营成长与现有英雄主动仍在这个因子之外；一次助攻/燃金与原资源消耗不变，允许爆发一击过关。
- 主线暖场400/900/1800/3600/6000/9000/14000/20475；无尽之后每章×1.1，场次×1/1.5/2、现有难度因子最后一次ceil。第13章32,976/49,463/65,951；没有先ceil暖场再乘阶段。
- 商店当前/本章预告与结算后下一场读取同一个身份目标；入场把精确值保存为initialTargetHeat和targetHeat。库存、金币、升级和出牌高低不改变锁定基础值。B14每次成功弃牌加ceil(initialTargetHeat/20)，不复利；例第8压轴40,950，每次+2,048。
- 原新局确认与规则详情说明新规则/重开与最多×4；未重排选角界面或模式入口。

## 给动态结算与回看的事件合同

保留 `phase=routeGrowth`、`operation=route-factor`、`sourceType=rule`、`sourceDefinitionId=route-growth`，以及 `reasonKey=route-growth.<G|S|F>.factor`。有符合族时**仅一个实际乘法事件**：routeFamily为实际取中的族，value为实际有理数因子，before/after为真实累积H/M，resourceBefore/After为该族手前清关计数。

新可选字段 `routePolicy: bounded-max-v1`、`routeCap: {n:4,d:1}`（保存值为十进制字符串）；trace.routeGrowth.factors记录本手各符合族的封顶候选，applied记录policy/factor/family/cap。例SF的S4/F8比较1.4与3.71293，选F，并且只乘3.71293一次。高牌applied.family=null、factor1，乘法事件0个。

现有 `route-clear` 与每族 `route-clear-family` 清关事件保持，表示真实计数新增，不是再次把倍率乘入本手。中文来源“过关加成”，作用说明“×当前值（最多×4）·取最高一项，不叠乘”。消费者应使用event.value，不能根据family再自行叠乘或把计数当本手增分。该元数据与选中因子/真实事件数均由保存校验重算并拒绝篡改。
