# 美术方向与独立任务书

## 1. 先作决定：统一画面语言，而不是加更多东方符号

建议主方向是**明亮、克制、带荒诞幽默的印刷巡演牌桌**。纸张、剪影、有限套色、轻微体积光形成统一语言；少量玉色、朱红和黄铜作为识别点。它不是春节活动页，不是全场金光的古风手游，也不是暗黑哥特赌场。

东方元素保留在人物身份、道具和节奏里，不要求每张卡都加云纹、元宝、印章、飞檐。现代无赖、古代游侠、未来表演者可以同台，但要共用同一光源、材质粗糙度、边缘语言、饱和度层级和卡框系统。人物风格不同不等于各自来自六款游戏。

“大丑”是角色身份的反差，不是把脸画丑或六个人都套同一件飘带长袍。当前原图尚未完成逐图视觉复审；以下是新制作指引，不伪称已看过并认定所有旧图失败。

## 2. 默认视觉语法

暂定方案 A：彩色印刷纸质舞台，偏平面插画而有可信的轻体积。作为对照只允许做一张方案 B：柔光定格/半3D纸偶版本。两者用完全相同的真实牌桌布局比较，不能分别挑最漂亮的孤立海报。优先推进 A，B 只有明确体验优势才替换；严禁把两套渲染方式直接混入同一版本。

色彩建议（是起点，不是堆满所有颜色）：米白 #F3EADB 用于可读卡面，墨蓝 #24313B 用于正文和轮廓，低饱和玉青 #5D9184 用于次层，朱红 #C84E42 用于关键动作，黄铜 #B79554 只点缀稀有/确认。深色可用于阴影和少数角色，但不吞掉整张画面的层级。

统一约束：光从左上前方；轮廓清晰，主体与背景至少有明度分离；角色眼神与关键道具在小尺寸可认；背景比卡牌低一档对比；高饱和和发光仅留给可交互/真正触发之处。普通扑克牌花色和点数必须由程序清楚绘制，不嵌在生成画里。

卡框仅三档：common 简洁纸边，uncommon 一处材质/纹样区别，rare 明确徽记与有限反光。不能靠细金丝数量区分稀有度。特殊纸张/玻璃/返场增强使用独立角标与辅助纹理，不新造一套每张都不同的卡框。

## 4. 资产复用判断，不为沉没成本扩3D

A00 先对现有六原图/六头像/39GLB/背景/精灵表生成联系表，按实际 UI 用途分类：可直接用、需重加工、仅保留源、待确认。尚未看过的填“未审”，不可填“通过”。

优先考虑复用几何母版（牌片、骰子、普通币）及脚本；材质、字样、背景可能要重新统一。3D母版可用于离线渲染卡片翻面与道具图，但 Phaser 中的扑克牌主体仍以2D贴图/可控变形表现。不得为了“用上39个模型”改主引擎。

不批量渲染“暴击、全场失控”等固定3D中文字作为主要UI；重要文字由字体/程序绘制，便于本地化、清晰度和真实数值联动。旧资源不删除，先移出运行时白名单。

## 5. 各批次输入、输出和停止线

### A00：盘点，不重画

输入：当前资产目录、asset-pack-v1.json、UX 分区和具体卡面可视尺寸。输出：带相对路径/像素/字节/用途的联系表；每项技术/视觉/接入三状态；新旧 rarity 映射；首屏与解码预算清单。

必须实际渲染 GLB/动画预览，检查翻面、弯曲、透明边、字样识别和过度反光。GLB validator 为零错误只是技术门槛，不是视觉评分。没有渲染环境时记录 NOT_RUN，不让执行AI凭文件名编观感。

### A01：金样，只做能决定方向的小套件

输入：通过灰盒的真实布局截图与事件时序，默认方案A和固定角色brief。输出上限：一张完整牌桌金样（1280×720与390×844两种布局）；阿默、阿燥两名反差角色半身/卡片预览；三种稀有度卡框各一张；三张机制不同的Joker示例；一套普通扑克牌角标；三档触发反馈示例。可另交一张方案B对照，不展开第二套全资源。

重要：牌桌里必须同时有目标/倍率、五个Joker槽、八张手牌、出牌/弃牌、金币和Boss提示；不能把实际信息删掉来让海报显得高级。所有中文数字使用后期字体排版，不接受生成模型乱码。

在实际 CSS 尺寸查看：64px头像仍认得人，手牌露出的点数/花色不混淆，14px文字对比清楚，Joker不同稀有度在灰度下也有符号区分。给用户确认的是这张“能玩”的完整画面，而非只挑立绘脸部。

**停止线：没有明确记录的样张批准，不扩正式角色批次、不扩72卡、不做高级3D/全套背景。** 用户2026-10-01随后明确要求重做现有六角色的差异与精致度，D11授权P00各一张胸像候选；这六张是评审输入，不是A03批准。如被否定，只修改被指出的视觉维度，保留已经认可的布局/规范，不整包盲重画。

### A02：接入规格样本

工程 Agent 负责把批准金样接入 Phaser，Astra 负责需要重导出的文件。检查手机触摸区、裁切、缩放、网络/解码、Alpha边缘、字体、过场。输出真实浏览器截图/短视频与资源清单，不能把PSD合成图冒充运行截图。

至少首屏缩略资源取代旧14.29MB原PNG预载；源图和GLB不进首屏；HUD使用独立头像，不再裁全身长图后非等比缩放。通过后冻结visualVersion、构图和导出规范。

### A03：逐批量产

输入：批准的视觉规范、稳定内容ID与已验收参考。角色按剩余四人分两批；Joker按每批6–12张；背景先牌桌/商店/Boss三种需求，不做八章八套完全不同UI。每批附联系表和真实卡面缩略预览，未通过的一批返工，已通过批次不一并重置。

动效先选牌/出牌/点数/+M/×M/重触发/奖励七类；三档强度复用材质和节奏，而非每张卡独立一段昂贵动画。音效/音乐需独立来源记录，不强求图像模型同时作曲。

## 6. 文件规格

| 用途 | 可编辑源/母版 | 运行时输出 | 审核点 |
| --- | --- | --- | --- |
| 角色立绘 | 至少1024×1536；背景/主体分层或透明PNG | 选角256×384或384×576 WebP；详情按需768px长边 | 安全区、完整轮廓、焦点坐标；不统一假定脸在y=.08 |
| 头像 | 独立正方裁切源，至少512×512 | 128/256px WebP，按DPR选择 | 64CSS px实际可识别，不能靠把全身图挤成方形 |
| Joker插画 | 512×704以上，无文字，无卡框烘焙 | 256×352/512×704，统一透明/不透明规则 | 小图符号与背景分离；同一mechanism不靠无意义花纹区分 |
| 卡框/角标 | SVG或高分辨分层源 | atlas或程序九宫格 | 不能改变点击边界，符号不只依赖颜色 |
| 背景 | 分层可编辑源，关键区留空 | 桌面/竖屏分别裁切，不强行同投影硬套 | 实际UI遮挡、对比、粒子不抢正文 |
| 特效 | 可重建工程/节点参数 | 透明atlas+JSON，12–24帧/效为初始预算 | 直Alpha约定、外扩padding、帧顺序/持续时间/边缘抽检 |
| 3D可复用源 | .blend/重建脚本+GLB+材质通道 | 默认离线渲染，不直接runtime加载 | UV/法线/动画/可替换节点；面数是上限不是必须凑够的下限 |

不要同时为同一资源加载两种分辨率。首屏资源预算见 QUALITY，具体每张字节上限由清晰度实测分配，不只为过字节门禁把脸压糊。需要更大资源时先给效果/成本对照，不悄悄抬总预算。

## 7. 交付manifest

每项至少：assetId、contentId、sourcePath、runtimePaths、previewPath、width/height/alpha、bytes/hash、crop/safeArea、用途、visualVersion、技术验证命令/日志、视觉批准记录、生成或制作工具/版本、原始输入/必要参数、来源与使用权限证据。商业使用资格未经核实的资产不得放入发布白名单。

生成图片要检查多余手指/肢体、饰品漂浮不合理、伪文字、水印、现成品牌标识和明显复刻角色。使用模型不自动等于人工质量验收；不能把 prompt 存了就算可重建，非确定输出保留实际母版与哈希。
