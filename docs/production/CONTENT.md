# 1.0 内容合同与扩展批次

本表提供可实现的机制和初始参数，不声称数值已经平衡。名字可经文案审查调整，定义 ID、时点、集合、状态寿命不能悄悄改。C/U/R分别为common/uncommon/rare，只有三种稀有度。按D21，闪箔/全息/多彩将成为独立战力版次，不能继续只画成视觉材质；版次不改变稀有度。本页第8节列扩展输入，精确新增条目/参数在C01.1定稿，当前尚未启用。

## 1. 全体内容规则

表内“计分牌”指 activeScoringIds，“持牌”指 heldIds，“每手”包含各次合法出牌但不含弃牌。数值 H/M 作用于 RULES 的累加器；所有 ×M 都在指定时点乘当前倍率。每实例成长初始 0（明确初始 ×1 的除外），持有期间跨场保留，出售/销毁清除；表内标明每场的计数则进场归零。afterHand 成长默认下一手生效。

onCardScore 在普通触发和重触发均会发生；“首次/第 N 张”由该手的原始计分牌序号决定，不把重触发误当新卡。产生重触发的来源只响应深度 0，最多额外四次/卡。所有 cap 都是真正引擎约束并在图鉴公开。

经济事件只针对成功事务。买入成长只由购买前已持有的来源触发，不给刚买到的投资牌凭空自成长。售出成长不包含售出自己。刷新成长仅支付了金币的刷新触发。随机奖品使用 reward RNG；库存满的转换值固定在表中，不自动覆盖旧物品。

静态修正通过 readModifiers 在明确阶段读取，不用无限事件回调互相监听。每张牌至少有：触发/不触发/边界/顺序/保存恢复五类用例；有随机/成长/重触发者增加相应专项。禁止只有 JSON 名称和描述、没有实际效果。

ID 约定：表左 A01 等是策划索引；括号内是运行时稳定 definitionId。五张既有 ID 保留：pengci/mantangcai/tiesuanpan/huimaqiang/jiedongfeng。其余使用 a03…f12；不要用中文显示名当 ID。

| B14 | 催场 | 每次成功弃牌使目标增加本场初始目标的5%，不复利，整数向上取整；免费返还次数仍算一次弃牌 |

关卡抽取使用 RULES 的章池；B01–B04 是灰盒首测。至少给每个 Boss 一个合理应对说明和两个交互用例；不能用“高倍数秒掉”代替验证规则实际生效。困难 Boss 的实际公平性必须由目标曲线与构筑实测判定。

## 7. 图鉴、文案与内容验收

每个条目需要普通描述（尽量≤两句）、精确展开、当前实例值、触发集合图示、稀有度/价格、解锁/获得方式、对应测试 ID 和资产 ID。默认不在卡面写故事长文；趣味文案放详情最末，不干扰算分。

内容表是初始化策划；落地后机制变更更新此合同，参数在版本化 balance 数据中改并自动生成表，禁止运行时数据与手写展示两份数值漂移。静态 schema 校验覆盖未知 ID、非法分母/概率、超过cap、引用不存在的物品/Boss、重复资源映射。

跨族必须测试的桥梁：单张+持牌、对子+成组重触发、花色改造+顺同成长、空槽+经济投资、少金币风险+买卖、最后一手+救场+余次奖励。复玩质量来自这些交互和取舍，不来自72张名字不同但数学相同的牌。
