# 质量重置决策

状态：本方案被采用后生效；实现状态一律看 plan.json。用户已要求全方位整改、以 Balatro 的核心体验为标杆、允许修改不合理工程、为新 AI 会话提供渐进文档，并把美术单独交给 Astra。以下是在这些约束下作出的工程和产品决定。

## D01：保留引擎，改变边界

保留 Phaser 3 + TypeScript + npm/Vite。领域命令、状态和计分从 Scene 中抽出，不整仓换框架。2D/2.5D 是运行时主线，Blender/GLB 可作为离线素材源。引入运行时 3D 必须同时证明视觉收益、设备预算与维护成本；已有 39 个模型不是引入理由。

## D02：r2 是规则升级，不是偷偷修旧测试

旧 GDD 明确要求加法统一完成后乘最终倍率，旧测试也按此断言。新方案改为普通牌点数参与、明确计分牌、按时点与装备顺序结算。必须标记 rulesVersion=r2，建立新金样例并保留旧语义的迁移说明，不将旧测试改绿后声称只是 bugfix。

## D03：先可玩的取舍，再内容规模

先补弃牌、查看牌组、排序、买卖替换、可解释结算与恢复，再做小型灰盒。旧下一步“先做 Boss 收尾”废止。首个灰盒只用两个易评估角色和 24 张定义完整的牌；不是把六个角色删掉，而是避免未验证系统同时叠六份变量。

## D04：统一视觉语法，不统一人物服装

新的方向为“明亮、荒诞、精致的巡演牌桌”。东方可以是气质与少量物件，不强制每处都用牌坊、云纹、元宝、红金装饰；也不转回暗黑哥特。六人可来自不同年代，但共用渲染、光照、材质、构图与 UI 规范。最终风格在真实牌桌金样中批准，禁止仅凭孤立大图扩产。

## D05：状态属于规则，不属于动画

成功命令先产生完整新状态和事件，并保存；动画只消费事件。退出、跳过、静音、降帧、刷新均不改变数学结果。UI、模拟器、自动测试、回放必须共用领域入口。

## D06：有限产品范围，质量不自降

1.0 目标范围见 PRODUCT：6 角色、72 大丑牌、18 消耗品、12 长期道具、16 Boss、8 章、4 难度、12 挑战。数量是排期范围，不是“已匹敌 Balatro”的证据。测试不达标时修设计或质量，不可改发布标准假装完成；重大范围变化由新决策记录说明理由与影响。

## D07：门禁不能靠口头

独立分支、PR、固定输入、CI 日志、交互 trace、实际设备记录、真人测试记录构成证据链。所有计划里的新命令在脚本真正存在前都标为未实现。审查工具本身需要反例测试，不因为有 check 脚本就默认保护有效。

## D08：兼容与预算

本轮不删除既有美术源文件，也不覆盖用户的新提交。旧 r1 原型没有正式存档合同；r2 若发现旧实验存档，只允许显式导出/保留并提示新开局，不静默套用新规则。文档、代码和素材的审查/批准状态分开记录。美术在独立小批次验收之前不扩产。

## 以后如何新增决策

新条目必须包含：问题、现有证据、至少一个替代方案、选择、对规则/存档/性能/素材的影响、迁移步骤、回滚点、验收人或批准来源。不得删除旧条目掩盖路线变化。
